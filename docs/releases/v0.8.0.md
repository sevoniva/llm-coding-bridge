# v0.8.0

`v0.8.0` adds a source-compatible custom-provider path for DeepSeek Harness while preserving the built-in official provider and the bridge's existing client routes.

## Highlights

- DeepSeek Harness can use the bridge through an `openai-completions` custom provider pointed at the local `/v1` endpoint; no Harness source change is required.
- Harness requests receive client-specific transport handling: empty assistant content in tool-call history is preserved, the safe attribution header allowlist is forwarded, SSE heartbeats remain protocol-valid, and upstream HTTP errors stay visible before streaming headers are committed.
- Provider and model configuration can translate an unsupported top-level `thinking` extension into `reasoning_effort`, including the explicit `none` value for disabled thinking.
- Provider and model configuration can cap `max_tokens` and `max_completion_tokens` at a tested upstream output limit.
- The compatibility behavior is covered by deterministic unit tests and real headless Harness tool-call and streaming acceptance checks.

## Upgrade

```bash
npm install -g @sevoniva/llm-coding-bridge@0.8.0
```

Existing version 1 and version 2 configurations remain supported. Add the custom Harness provider in Harness itself; the built-in `deepseek-official` provider remains available alongside it.

## Validation

The release gate, complete test suite, static security scan, secret scan, dependency audit, package dry run, and real local Harness headless acceptance checks passed before release. The published package does not contain credentials or machine-specific configuration.

## Rollback

Version `0.7.0` remains available:
