# v0.9.0

Edit one configuration file, double-click restart, and point ZCode at the local bridge.

## Configuration and scripts

- `init-files` creates a private `config.json` and clickable start, restart, stop, status, and disable-autostart scripts. Existing configuration is preserved when scripts are regenerated.
- The simple configuration accepts `upstream.baseUrl`, `upstream.model`, and `upstream.apiKey`. Keys are omitted from effective configuration, migration previews, and administration responses.
- Restart scripts load the configuration beside the script, check that its revision is running, and display the ZCode base URL, model, and local credential instructions.
- UTF-8 BOM, Unicode paths, spaces, and Windows batch path escaping are supported.
- `config path`, `config validate`, `service-status`, and `stop-service` make configuration and service state inspectable.

## Windows and macOS

- Windows uses a current-user Task Scheduler logon task with hidden execution, appended logs, single-instance behavior, and bounded failure restarts.
- macOS continues to use launchd. Both platforms start after the user logs in; this is not a pre-login system service.
- Service restart reuses the registered configuration path and refreshes the absolute Node and package paths.
- The optional wizard supports Windows DPAPI credentials, macOS Keychain, and Codex / Claude Code / ZCode client setup. Windows private files use current-user ACLs.
- The Chinese quick-start guide leads with the single-file and clickable-script workflow; wizard automation has a separate guide.

## Reliability and maintenance

- Provider concurrency limits apply to individual upstream attempts, so a timed-out attempt releases its slot before retrying and queued requests can proceed.
- Updated the `fast-uri` and `js-yaml` development dependencies to patched versions.
- Added Windows CI on Node 18, 20, 22, and 24, native DPAPI/ACL and Task Scheduler definition checks, background request coverage, and installation tests against the packed npm package.
- Interactive Windows logout/login and physical sleep/wake acceptance require a desktop session and are not simulated by CI.

## Upgrade

```text
npm install -g @sevoniva/llm-coding-bridge@0.9.0
llm-coding-bridge init-files
```

Fill `baseUrl`, `model`, and `apiKey` in the generated `config.json`, then double-click `restart.cmd` on Windows or `restart.command` on macOS. ZCode uses `http://127.0.0.1:37629/v1`, the configured model, and `local` as its API key unless a local token was configured.

If files were generated in another directory, rerun `init-files --out <same-directory>` to refresh the scripts while keeping the configuration. Existing v1 and v2 configurations remain supported.
