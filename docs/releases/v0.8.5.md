# v0.8.5

`v0.8.5` prevents agent fan-out and bridge retries from overwhelming rate-limited upstream providers.

## Reliability

- `server.maxConcurrentRequestsPerProvider` adds a cancellable FIFO limit for complete request chains per provider.
- `server.minRequestIntervalMsPerProvider` enforces a minimum interval between every upstream attempt, including retries.
- Queue and pacing waits emit `upstream_queue_wait` and `upstream_rate_wait` administration events without consuming retry attempts.
- A limit of `1` plus a suitable start interval lets bursty clients such as DeepSeek Harness wait locally instead of repeatedly receiving upstream HTTP 429 responses.

## Validation

The concurrency, pacing, configuration, and DeepSeek Harness compatibility suites pass alongside lint, the complete test suite, fault-soak coverage, static security and secret scans, repository and release gates, dependency audit, and package dry run. Three concurrent real local DeepSeek Harness headless tasks also completed successfully with seven-second upstream start pacing and no HTTP 429 response.
